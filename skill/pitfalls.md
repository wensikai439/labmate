# 踩坑清单

用于准备提示输入、审查修正方案和设计验收。每项都对应实际失败或已有测试覆盖的观察；模拟案例不作为现场故障记录。

<a id="s1"></a>
## S1 回复成功，设备波形仍不符

- **触发与现象：** 连续 SCPI 设置后云端有回复，但目标 SIN 回读为 SQU，旧程序返回码 1。
- **判断依据：** 单独发送长/短正弦指令均回读 SIN；不能由网络回复或单条指令成功推断整段配置成功。
- **排查顺序：** 核对设备/通道 → 对齐目标和原始命令 → 找第一个回读不符点 → 查模式切换、完成等待与错误队列 → 区分发送前拒绝和发送后失败。
- **修正办法：** 对关键状态切换逐段等待、查错与回读；失败停止后续设置，沿用输出状态保存和恢复流程。
- **验证：** 回读波形与幅度、返回码、初始/最终输出状态；历史三组均为 SIN、返回码 0，幅度 2/1/2 Vpp，输出状态保持 0/1/1。
- **适用条件：** 设备具备相应查询接口；其他协议需替换完成信号与错误查询。配置回读与物理测量分别验收。

入口：[S1 提示](prompts.md#s1)；来源：[C1](collaboration.md#c1)、[旧失败](evidence/old-reproduction.json)、[修复记录](evidence/candidate-hardware.json)。

<a id="s2"></a>
## S2 刷新周期和数据年龄混用

- **触发与现象：** 读数耗时、忙时变化和控制完成事件改变调度顺序，可能造成漏刷或慢读后连续补刷；这些情形已纳入模拟测试。用户同时要求保留三卡与底部统一时间。
- **判断依据：** 整轮完成时间表示一轮结束，单台年龄表示该台数据新鲜度，两者用途不同。
- **排查顺序：** 标记事件到达、取得读取权、各设备读完与整轮完成时刻 → 检查事件何时消费 → 比较各卡时间来源 → 核对单台 stale。
- **修正办法：** 周期从整轮完成后计算；忙时保留事件、合并突发事件；及时发布读到的参数，整轮结束再更新共享轮次。
- **验证：** 5 项调度测试覆盖完成后计时、忙时事件、读取中事件、慢读和控制完成；界面同时核对高亮、三卡/底部时间与过期恢复。
- **适用条件：** 项目要求一组设备共享完成周期；先明确设备清单及超时处理。独立采样任务不必照搬整轮语义。

入口：[S2 提示](prompts.md#s2)；来源：[C2](collaboration.md#c2)、[调度测试](../sim/historical/file_b19f499ecdf0/test_refresh_legacy.py)、[历史界面记录](evidence/local-test-results.json)。

<a id="s3"></a>
## S3 常驻降低等待，却在长任务中耗尽内存

- **触发与现象：** 语音与视觉共存时，长录音识别耗尽内存，浏览器进程被系统结束。
- **判断依据：** 稳态可运行不能说明识别峰值可承受；暂停计算也不等于释放模型内存。
- **排查顺序：** 对齐录音时长与内存峰值 → 区分停录和音频采集完成 → 列出资源所有者与 active/desired 状态 → 检查加载、取消和失败后的恢复路径。
- **修正办法：** 按实测加入时长和内存保护；任务空闲后切换，资源取得与释放配对；需腾出内存时释放所属模型进程，恢复失败保留重试状态。
- **验证：** 历史连续两次 6 秒录音无新增内存崩溃且摄像头恢复；后续归档含 38 个模型检查点、三轮模式切换及五分钟共存观察，23 项综合检查包含文档处理资源恢复。
- **适用条件：** 多任务共享有限内存且可控制模型生命周期；换板卡、模型或输入长度后重新测峰值和恢复行为，历史 6 秒限制不直接成为新项目阈值。

入口：[S3 提示](prompts.md#s3)；来源：[C3](collaboration.md#c3)、[模型检查点](evidence/model-checkpoints.json)、[综合检查](evidence/ds-integration.json)。

<a id="s4"></a>
## S4 后台有总结，页面未展示；不同轮次结果易混用

- **触发与现象：** 用户完成实验后看不到总结，检查发现浏览器停留在旧页面。归档时还存在有测量的真人测试轮与无回执的新轮，需分别记录。
- **判断依据：** 后台持久化结果与实际页面展示是两个验收点；结果归属依赖稳定轮次标识。
- **排查顺序：** 核对浏览器页面版本 → 查本轮状态与总结 → 按 run_id 对齐作业 → 分开当前设置和已验证测量 → 重放重开后迟到响应的模拟顺序。
- **修正办法：** 页面更新后验收实际呈现；按本轮筛选回执，成功且已验证的测量回执用作测量依据，设置操作回执与当前设置单列，失败作业保留错误；重开清除旧总结，下一次开始生成新轮次。异步保存核对流程仍为 completed 且 summary.id 与原请求令牌相同。
- **验证：** 7 项测试覆盖归属、重启、重复请求、迟到响应、云端失败和旧对话隔离；页面验收另核对所见总结是否属于本轮。
- **适用条件：** 系统具备持久化任务标识和可信回执；缺失测量时不得以设置快照填补结果。

入口：[S4 提示](prompts.md#s4)；来源：[C4](collaboration.md#c4)、[总结测试](../sim/historical/file_b19f499ecdf0/test_experiment_summary.py)、[综合检查](evidence/ds-integration.json)。

<a id="s5"></a>
## S5 一次 ready 不能证明后台持续可用

- **触发与现象：** 曾确认连接成功，后来转发进程退出；重新插线后串口已识别，仍不能通信。
- **判断依据：** 历史排查发现后台进程未运行，缺少登录启动及退出后恢复。旧日志的 ready 不属于当前运行状态。
- **排查顺序：** 查当前服务/任务与唯一目标进程 → 对齐 PID 和启动段 → 查最近重连后的 ready → 查退出与人工停止标记 → 用模拟事件检查重试和停止。
- **修正办法：** 配置后台启动，连接失败延迟重连；人工停止退出循环。先前失败请求由用户重发，避免恢复连接时重复执行控制。
- **验证：** 4 项重连测试、11 项就绪案例；历史板卡探针收到 3 次回复，工作区与对话摘要前后一致，未执行仪器控制。
- **适用条件：** 能识别服务进程、启动段和停止信号；端口被其他维护任务占用时先协调，不能以强占端口验证重连。

入口：[S5 提示](prompts.md#s5)；来源：[C5](collaboration.md#c5)、[重连测试](../sim/test_relay_runner.py)、[就绪案例](../sim/test_relay_startup.ps1)、[历史探针](evidence/ds-reconnect.json)。
