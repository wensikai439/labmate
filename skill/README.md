# LabMate 可复用开发技能

本目录提供仪器控制、整轮刷新、模型调度、实验总结与串口转发五项开发技能，来自 LabMate 的实际协作和纠错记录。每项包含可复用提示流程、工程对应位置、验证结果和失效条件。

## 第一次使用

先按问题选择 S1—S5，再准备该项列出的源码和原始记录；复制 [prompts.md](prompts.md) 中对应提示并替换方括号输入。人工核对模型的判断与证据后，在自己的工程中实施修改，最后按验收条件记录环境、日期、预期值、实际值及失败项。[踩坑清单](pitfalls.md) 可在分析和验收时对照使用。

五项是技能主题；主要交付形式为提示词工作流和结构化踩坑清单，配套工程回归、材料自检与来源记录：

| 交付形式 | 内容与入口 | 复用方式 |
| --- | --- | --- |
| 提示词工作流 | [五项提示](prompts.md)，含输入、步骤、输出及验收条件 | 可单独复制，按字段对应表替换项目输入 |
| 踩坑清单 | [pitfalls.md](pitfalls.md)，含现象、判断依据、排查、修正和验证 | 可单独用于评审、排查和验收 |
| 配套工程回归工具 | [run_checks.py](run_checks.py)、[检查与迁移说明](checks.md) | 重跑已有功能测试，需完整 LabMate 工程及 Windows/PowerShell；用于验证工作流涉及的实现 |
| 辅助材料自检工具 | [verify_evidence.py](verify_evidence.py) | 检查随包 evidence 的完整性和记录一致性 |
| 历史案例与使用示例 | [协作记录](collaboration.md)、提示中的短示例及 evidence | 用于理解方法和追溯来源 |

提示流程从历史协作中整理；效果依据为对应工程记录与代码测试。其他项目先替换协议、状态字段及测试适配，再记录自己的验证结果。

本目录已位于完整提交材料的 `labmate/skill/`，与 `src/`、`sim/` 配套使用。提示与清单可直接阅读；归档核验及 LabMate 示例回归从当前 `labmate/` 根目录执行下列命令。工程依赖、默认值及首次运行前置条件见 [工程对应与复现边界](engineering.md)。

| `evidence/quotes.json` | 按对话、轮次、时间定位的原文短摘录 |

| `verify_evidence.py` | 离线检查证据完整性及已记录结果 |
| `run_checks.py` | 在临时副本中重跑工程已有的刷新、回执和转发测试 |
| `evidence/reuse-results.json` | 2026-11-01 离线复用归档 |
| `evidence/current-results.json` | 2026-11-02 针对交付工程 ZIP 的 27 项离线回归 |

下文 `dashboard/` 为 `src/boot/labmate-control-v2/dashboard/`。先在终端进入交付工程根目录 `labmate/`（该目录下应同时存在 `skill/`、`src/`、`sim/`），再执行：

```text
python -B skill/verify_evidence.py
python -B skill/run_checks.py --project-root . --only all --output ../skill-check.json
```

第一条使用 Python 标准库，检查随包证据；第二条需要 Python 3 和 Windows PowerShell，归档运行环境为 Windows 11、Python 3.12.14。也可用 `--only refresh`、`receipts` 或 `relay` 单独检查；临时目录受限时，可用 `--work-dir <可写目录>` 指定工作位置。测试使用模拟时钟、临时工作区、模拟云服务和转发替身，不连接板卡、仪器、串口或云端。模型调度和仪器控制采用历史记录核验，实机结果保留原采集日期。

## S1 仪器命令完成与参数回读

- **适用范围：** SCPI 仪器连续设置后，执行返回成功与设备状态不一致的排查；可用于具有完成查询、错误查询和参数回读接口的其他设备。
- **输入：** 设备标识、通道、原始写入与查询顺序、错误队列、设置前后读数、原输出状态。
- **操作：** 用 [S1 提示](prompts.md#s1) 拆分“命令已发送、设备已完成、目标参数已回读、输出状态已保存”；先复现原失败，再对模式和波形切换逐段等待、查错与核对回读。
- **输出：** 最小故障序列、协议层修改点、参数/状态对照表与恢复记录。对应 `src/boot/labmate-control-v2/src/channel_control.c` 及 `dashboard/control.py`。
- **已验证效果：** 2026-10-30 旧程序返回码 1，正弦设置后回读仍为方波；修正后 3 组案例均回读正弦、幅度正确，输出状态分别保持 0、1、1。证据见 `evidence/old-reproduction.json` 与 `candidate-hardware.json`。
- **失效条件与边界：** 设备没有完成或回读接口时，本流程不能确认执行完成，需补充可观察状态或测量手段。单条指令成功不能推出连续配置成功；参数回读确认的是设置值，波形的物理测量另需测量回执。本技能复用时先做日志分析与模拟验证；实机操作须沿用现场授权和状态恢复流程。
- **案例归档核对：** `python -B skill/verify_evidence.py`。新项目按 S1 验收表重新核对实际参数回读、错误队列与状态恢复。来源 [C1](collaboration.md#c1)、[C2](collaboration.md#c2)，排查见 [S1](pitfalls.md#s1)。

## S2 三台仪器整轮刷新

- **适用范围：** 多设备轮询界面需要及时显示变化，同时共用一轮完成时间；适用于多传感器采集面板和测试台轮询调度。
- **输入：** 调度器、单台快照、变化事件、控制完成事件、界面时间和高亮逻辑。
- **操作：** 用 [S2 提示](prompts.md#s2) 保留单台年龄作过期判断；整轮读完再更新共享 `round_revision` 和 `round_age`；忙时记录后续刷新事件，合并突发事件。
- **输出：** 调度时序、刷新与过期判定的职责划分，以及控制完成/慢读/突发事件的检查结果。对应 `dashboard/polling.py`、`instruments.py`、`panel.py`，共享时间和页面呈现另见 `server.py`、`app.js`。
- **已验证效果：** 2026-10-30 的界面记录包含及时回读、绿色高亮、统一时间、过期恢复和无页面错误；2026-11-01 归档重跑 5 项已有调度测试，结果见 `evidence/reuse-results.json`。
- **失效条件与边界：** 设备清单或完成边界未定义时，无法判定整轮完成；先明确超时和缺席设备的处理策略。整轮时间不能代替单台数据年龄；连续慢读不应形成补偿性连读。离线调度测试覆盖事件与时序，界面高亮仍以历史界面记录为依据。
- **复用检查：** `python -B skill/run_checks.py --project-root . --only refresh`。来源 [C2](collaboration.md#c2)，排查见 [S2](pitfalls.md#s2)。

## S3 受限内存下的模型调度

- **适用范围：** 本地语音、视觉与指导书处理共用有限内存，需要在模式切换和异常后恢复；可用于边缘设备上多个模型或内存密集任务的资源交接。
- **输入：** 活跃/期望语音引擎、任务占用、模型生命周期、可用内存、录音时长和异常日志。
- **操作：** 用 [S3 提示](prompts.md#s3) 画出占用与恢复状态；任务空闲后再切换；加载失败保留真实状态；所有让出资源的路径都配对恢复。指导书使用资源租约，恢复失败保留可重试状态。
- **输出：** 状态转移表、内存峰值记录、正常/失败/切换中的恢复检查。对应 `dashboard/asr_engine.py`、`model_runtime.py`、`voice.py` 和 `guide_resources.py`。
- **已验证效果：** 历史长录音发生过内存耗尽与浏览器退出；随后加入 6 秒限制、采集结束与内存保护。2026-10-28 的记录含 38 个模型/视觉/按键检查点、错误数组为空，并记录三轮本地/Hy 切换及五分钟共存观察；23 项 DS 综合检查含文档处理后的资源释放与恢复。原文与文件见 C3、C4。
- **失效条件与边界：** 只有稳态内存、没有任务峰值或异常路径记录时，不能据此确定安全阈值。常驻减少加载等待也增加内存峰值；进程暂停通常仍占内存，指导书处理采用所属进程组释放。该组记录覆盖三轮模式切换和五分钟共存运行，检查项见证据文件。
- **案例归档核对：** `python -B skill/verify_evidence.py` 核验归档检查点和错误记录；新项目重新测峰值内存，并验证模型切换、失败与取消后的资源恢复。来源 [C3](collaboration.md#c3)、[C4](collaboration.md#c4)，排查见 [S3](pitfalls.md#s3)。

<a id="s4"></a>
## S4 实验回执归属与异步结果隔离

- **适用范围：** 实验规划、语音操作、测量和自动总结共用持久化工作区；可用于具有任务批次、异步作业和结果汇总的其他系统。
- **输入：** 当前 `workflow.run_id`、作业类型 `name`、`workflow_run`、`state`、`result.verified`、测量证据和总结标识。
- **操作：** 用 [S4 提示](prompts.md#s4) 按 `workflow.run_id == job.workflow_run` 选取本轮作业；仅成功且已验证的回执能证明已执行操作，再按操作类型区分测量与设置，失败作业保留错误。异步回写核对当前流程仍为 `completed` 且 `summary.id` 等于请求令牌；重开清除旧令牌，下一次开始生成新轮次。
- **输出：** 本轮事实、当前设置、失败记录、总结引用及迟到结果处理结果。对应 `dashboard/experiment_summary.py` 和 `workspace.py`。
- **已验证效果：** 历史 DS 综合检查含自动总结和重开清理；2026-11-01 归档重跑 7 项已有测试，覆盖轮次匹配、设置与证据区分、重复请求、重开后的迟到响应和云服务失败。
- **失效条件与边界：** 缺少稳定轮次标识或可信回执时，不能可靠区分结果归属；应先补齐记录。后台已生成总结还需检查浏览器实际展示；历史上旧网页缓存曾显示旧完成页。两轮实验的测量数值必须保留各自归属。
- **复用检查：** `python -B skill/run_checks.py --project-root . --only receipts`。来源 [C4](collaboration.md#c4)，排查见 [S4](pitfalls.md#s4)。

## S5 DS 转发启动就绪与断线重连

- **适用范围：** Windows 后台串口转发的登录启动、断线恢复与人工停止；可用于同类后台网关。迁移到其他系统时需替换进程、服务和停止信号的检查方式。
- **输入：** 任务状态、后台进程数量/命令行/PID、本轮启动日志、停止标记、重连/退出事件。
- **操作：** 用 [S5 提示](prompts.md#s5) 将就绪定义为唯一正确后台进程、当前 PID 的启动段、最近重连之后的 `UART relay ready`，且未停止/退出；连接失败延迟重连，人工停止退出循环。
- **输出：** 就绪判定结果、重连状态机、停止行为及请求处理边界。对应 `src/pc-background-launcher/run_cloud.py`、`start-background.ps1` 与 `src/pc-relay/start-cloud.ps1`。
- **已验证效果：** 2026-11-01 记录显示修正前后台进程未运行；修正后板卡连续收到 3 次 DS 回复，前后工作区摘要一致，`instrument_control_executed=false`。2026-11-01 归档重跑 4 项 Python 重连测试和 11 项 PowerShell 就绪案例。
- **失效条件与边界：** 日志不能关联当前进程和启动段时，不能依靠 ready 文本判定就绪。旧日志出现 ready 不能证明当前进程就绪；重连恢复后，先前失败请求由用户重新发起，避免自动重复执行。现场端口占用需要另行协调。
- **复用检查：** `python -B skill/run_checks.py --project-root . --only relay`。该入口只提取测试函数并使用替身，不运行启停脚本主体。来源 [C5](collaboration.md#c5)，排查见 [S5](pitfalls.md#s5)。

## 记录与验证

`collaboration.md` 将原始提示、模型判断、用户纠正、工程改动和证据逐项对应。引文可通过对话 ID 与轮次 ID 定位，导出的 `quotes.json` 供离线阅读。开发协作使用 Codex，DS 和 Hy 为应用运行服务。

`evidence/manifest.json` 保存文件摘要；`verify_evidence.py` 检查文件完整性和记录中声明的结果；`run_checks.py` 重跑已有工程测试。历史实机记录、历史界面记录与离线重跑分别列出，采集时间以协作记录为准；板卡历史系统时钟存在偏差，开发日期采用协作记录中的时间。

归档 `evidence/reuse-results.json` 保留 2026-11-01 的 27 项离线运行；`evidence/current-results.json` 保存 2026-11-02 从交付工程 ZIP 读取依赖后重跑的 27 项结果、源码摘要及工程 ZIP 摘要。重新运行请另存输出，保留各自日期。S1、S3 引用历史板卡记录；27 项离线测试覆盖 S2、S4、S5 的对应工程实现，不代表重新进行了实机、界面或模型性能测试。
